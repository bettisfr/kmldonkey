# KMLDonkey Qt6 / KDE Frameworks 6

## Ubuntu 26.04 build dependencies

```sh
sudo apt install build-essential cmake ninja-build extra-cmake-modules dpkg-dev \
  qt6-base-dev qt6-5compat-dev libkf6config-dev libkf6coreaddons-dev \
  libkf6dbusaddons-dev libkf6codecs-dev libkf6i18n-dev libkf6xmlgui-dev \
  libkf6widgetsaddons-dev libkf6completion-dev libkf6kio-dev \
  libkf6notifications-dev libkf6iconthemes-dev
```

The project requires C++17, CMake 3.22 or newer, Qt6, and KDE Frameworks 6.3
or newer. KDE style and icon initialization follow the user's desktop settings.
The `Qt6::Core5Compat` dependency is a **Qt6** module used for legacy regular
expressions and protocol text codecs. Qt4, Qt5, and KDE4 are not used.

## Build an installable package

```sh
./scripts/build-deb.sh
sudo apt install ./build-qt6/kmldonkey_2.1.5+qt6.12_amd64.deb
```

The script configures a Release build with `/usr` as the install prefix, builds
the application, runs its tests, and creates a `.deb` using CPack. It does not
install anything on the build host. The default build directory is `build-qt6/`;
an alternative directory can be supplied as its first argument. Set `BUILD_JOBS`
to change the default parallelism of four jobs.

The package installs the application in `/usr/bin`, its Qt6 protocol library in
`/usr/lib/<architecture>`, and icons, menus, and notification definitions in
`/usr/share`. The Qt6 library has SONAME 6, distinct from the KDE4 library's
SONAME 5. No per-user installation or references to the source checkout are
needed to run the installed application.

Runtime library dependencies are generated by `dpkg-shlibdeps`; `apt install`
resolves them from the target distribution. Build the package on the distribution
release and architecture where it will be installed.

Remove it with `sudo apt remove kmldonkey`.

## Build and test without packaging

```sh
cmake -S . -B build-qt6 -G Ninja \
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build-qt6 --parallel 4
ctest --test-dir build-qt6 --output-on-failure
```

Tests use an offscreen Qt platform, temporary configuration directories, and
local simulated MLDonkey and HTTP servers. They do not connect to a public P2P
network or change the user's KMLDonkey settings. Set `BUILD_TESTING=OFF` at CMake
configuration time to omit the test executable.

## Port status

The desktop application, protocol library, and their automated tests have been
checked with Qt 6.10.2, KF6 6.24.0, GCC 15, and CMake 4.2 on Ubuntu 26.04 amd64.
Package generation and startup of the extracted package outside the source tree
have also been checked. The obsolete Plasma applet and MeeGo UI have been removed.
The classes in `compat/` adapt the inherited box layouts and dialog APIs to
Qt6 / KF6 widgets, including shared KDE titles, buttons and text prompts.

Initial manual use with the companion MLDonkey OCaml 5 port has exercised
searches, live downloads, completed files and folder configuration. Broader
regression and desktop integration testing remain necessary before a stable
release. The HTML viewer supports basic HTML,
link submission, and history; it delegates complex pages to the external browser.
